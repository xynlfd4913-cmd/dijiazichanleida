# 低价资产雷达：产品定义与 Phase 0 边界

## 1. 产品使命

低价资产雷达服务于资金有限、希望恢复现金创造能力的中重度负债人。产品不把“低起拍价”当作机会，而是把资产放入用户的真实约束中判断：

1. 生活保障资金是否完全隔离；
2. 当前资产本金是否覆盖现金门槛；
3. 所有可识别费用计入后是否仍有安全价差；
4. 资产是否符合用户的技能、地区、仓储和运输能力；
5. 自用生产或保守转售是否能形成可验证的收入。

核心循环是：

`生活保障 → 积累资产本金 → 发现候选资产 → 核验全口径成本 → 生产或转卖 → 利润分配至本金与化债账户 → 提升本金等级`

本产品不是债务法律咨询工具，也不承诺收益，更不执行竞价、付款、借款或购买。

## 2. 设计原则

- 生活保障优先：`living_reserve` 不得成为可购买预算。
- 预算来自 `available_capital` / 资产本金账户，而不是总现金。
- 未知费用不是 0；未知即待核验，并降低成本确定性评分。
- 保证金通常不重复计入最终成本，但必须计入最低现金门槛。
- “评估价折扣”只用于背景展示；核心判断基于保守快速变现价与全口径最大成本。
- 所有金额、评分和出价上限由确定性代码计算，AI 只能抽取与解释文本。
- 不显示“必买”“稳赚”或“稳赚不赔”。输出是筛选与尽调辅助，不是购买指令。
- 原始公告、附件、字段来源与计算输入均应可追溯。

## 3. 目标用户与约束

核心用户具备劳动、技能或经营能力，但启动本金有限。用户画像至少包含：

- 可用资产本金与每月新增本金；
- 独立的生活保障金；
- 所在城市与搜索半径；
- 技能、仓储、车辆等履约条件；
- 偏好资产类别和策略（生产、转卖或混合）；
- 单项最大暴露金额。

相同资产对不同用户可以得到不同结论。比如一台需要维修和三相电的设备，对有电工技能和车间的用户可能是生产资料，对无仓储用户则应降级或跳过。

## 4. 三账户模型

| 账户 | 作用 | 是否可用于购买资产 |
| --- | --- | --- |
| 生活保障账户 `living_reserve` | 房租、食物、水电、通信、基础交通与家庭刚性支出 | 否 |
| 资产本金账户 `asset_capital` | 雷达筛选、保证金与资产全口径支出的唯一预算来源 | 是 |
| 化债账户 `debt_repayment_fund` | 债务协商、结清或分期还款的资金记录 | 否 |

系统只记录和建议资金分配，不代替用户转账或还款。

## 5. 本金等级

| 等级 | 资金范围 | 产品策略 |
| --- | ---: | --- |
| L0 | 0–2,999 元 | 生存保障、观察、收藏和积累，不主动推荐高风险交易 |
| L1 | 3,000–4,999 元 | 小工具、小设备和低现金门槛生产资料 |
| L2 | 5,000–9,999 元 | 小型设备、清仓工具、小额库存 |
| L3 | 10,000–29,999 元 | 小型机器、批量库存、部分小额拍卖资产 |
| L4 | 30,000–49,999 元 | 成套设备、商用车辆、小型清算资产 |
| L5 | 50,000–99,999 元 | 车辆、工业设备、成套资产或资产包 |
| L6 | 100,000 元及以上 | 不动产与需要复杂尽调的大额经营资产 |

实现时以项目内的资本等级纯函数为准；展示层不得绕过本金适配规则。

## 6. 机会判定

核心指标：

```text
safe_margin = conservative_resale_value - all_in_cost_max
safe_roi = safe_margin / all_in_cost_max
max_recommended_bid = conservative_resale_value
                      - non_bid_costs
                      - target_profit
                      - risk_reserve
```

机会总分为 100 分：本金适配 25、安全价差 25、流动性 20、技能适配 15、费用确定性 10、距离和处置便利 5。等级仅表达人工核验优先级：S / A / B / C / Skip。

生产型资产另外展示预计月增收和回本月数。该估计必须来自明确输入或人工维护数据，不能由模型凭空猜测。

## 7. MVP 信息架构

- 首页：三账户状态、本金等级、升级距离、扫描漏斗和重点机会。
- 低价资产雷达：来源、地区、预算、类别、阶段、用途与截止时间筛选。
- 资产详情：拍卖价格、保证金、费用明细、成本区间、保守变现价、安全价差、ROI、最大建议出价、技能匹配、证据和待核验项。
- 我的订阅：预算、地区、半径、类别、ROI、未知费用数和用途偏好。
- 关注列表：价格、状态、阶段、附件、公告、费用状态和截止时间的变化。
- 资本阶梯：本金增长与利润分配记录。
- 设置：画像、技能、履约能力和风险约束。
- 后台：来源健康、解析错误、结构变化、快照、人工修正和市场参照。

## 8. Phase 0 已定义范围

Phase 0 是本地单机 MVP 和工程边界验证阶段：

- FastAPI / SQLite 业务模型与确定性计算；
- Next.js 页面与模拟数据；
- 统一来源 Adapter 合约；
- 阿里捡漏 fixture-only 骨架；
- 本地 API、浏览器、会话元数据、调度与快照脚手架；
- 单元测试、至少 30 条覆盖典型资产和未知费用的种子数据；
- 不依赖任何真实拍卖网站即可演示完整筛选路径。

验收画像：资产本金 5,000 元、地区湖北、技能木工。系统应能从模拟资产中给出个性化机会，并解释被排除资产的本金、费用、地区或技能原因。

## 9. Phase 0 明确不做

- 不连接阿里或其他真实拍卖网站；
- 不探测私有接口，不启动 Playwright，不保存真实登录凭证；
- 不绕过验证码、登录、访问控制、robots 或限速；
- 不自动竞价、购买、付款、贷款或借款；
- 不让 AI 计算金额、猜市场价或替用户作最终购买决定；
- 不把缺失价格、费用或产权信息补成 0 或“无风险”。

## 10. 成功指标

产品不以“抓取总量”单独衡量成功。完整漏斗依次关注：扫描数、本金符合数、地区符合数、通过费用过滤数、存在有效市场参照数、安全价差合格数、技能匹配数，最终只把少量真正值得人工核验的候选推给用户。
